# FreeLocalPlayer — этап 0-C.1: фоновые сохранения медиатеки

**Статус:** пакет подготовлен; Android Gradle, обновление телефона и производительность на большой библиотеке должны быть отдельно проверены пользователем. Это **не миграция на Room**.

## Версия

- Android `1.3.11` / `versionCode 19` поверх принятой 0-B.1 (`1.3.10` / `18`).
- Без изменения `applicationId=com.example.freelocalplayer`, подписи, формата `local_library_v1`, UUID, MediaStore-идентичности, TXT/LRC, MIDI, исправлений, системного выбора файлов и содержимого ZIP-архива 0-A.

## Изменения

1. `LibraryStore.save(state)` перестаёт строить полный JSON и вызывать SharedPreferences на главном потоке. Передаёт неизменяемую ссылку на снимок очереди `LatestSnapshotWriter`. Однопоточный исполнитель сохраняет последнее состояние через `SharedPreferences.Editor.commit()`. Быстрые промежуточные снимки объединяются, но **последнее полное состояние** не выбрасывается.
2. Все операции чтения JSON при старте проходят внутри `Dispatchers.IO` **после ожидания** завершения записей предыдущей Activity. При ошибке декодирования приложение показывает блокирующий экран и не создаёт молча пустую, доступную для перезаписи библиотеку.
3. При экспорте SAF ZIP и перед восстановлением ZIP очередь сохранения обязательно опустошается на `Dispatchers.IO`. Импорт не может быть перезаписан отложенной записью старой библиотеки.
4. MediaStore-запрос уже выполнялся на IO. Теперь объединение найденного списка с `LibraryState` (`addMedia` для тысяч записей) выполняется на `Dispatchers.Default`; применяем результат на UI-потоке только если исходный снимок **не изменился**. При параллельной правке повторяем вычисление; при частых конфликтах останавливаем сканирование без перезаписи.
5. Аналогичная фоновая обработка применяется при добавлении целой папки через SAF. Установленное ранее быстрое индексирование 0-B.1 сохраняется.
6. Добавлены семь unit-тестов `LatestSnapshotWriterTest` для порядка, объединения, барьера, ошибок и поведения рабочего потока.

## Известные ограничения

- Фоновая очередь **не заменяет транзакционное хранилище**. Последние изменения могут не попасть на диск при немедленном аварийном завершении процесса до `commit()`. Поэтому до миграции Room сохраняем пользовательский экспорт ZIP 0-A и отдельно проверяем время сохранения.
- `changeLibrary` в UI всё ещё вычисляет некоторые небольшие пользовательские операции синхронно; с десятками тысяч записей это может вызывать задержки. Переход на Room/репозиторий и поток состояния — следующий этап после измерений и миграционных тестов.
- Ни идентификаторы треков, ни привязки медиа к ним не меняются. Данные из приватного каталога по-прежнему доступны при той же подписи и пакете.
- Инструменты `A–B`, `LRC`, `MIDI`, система автоматических аккордов, видео и UI-темы не меняются.

## Приёмка (не подменять сборкой)

1. До установки 1.3.11 создать и сохранить **вне телефона** резервный ZIP из текущей версии, убедиться, что архив открывается и содержит `manifest.json` и `prefs.json`.
2. `:app:assembleDebug :app:testDebugUnitTest`, все тесты PASS. Проверить, что `applicationId` и ключ подписи прежние; установить APK через `adb install -r` **без удаления приложения**.
3. Сравнить количество треков, тексты, плейлисты, избранное и список исправлений до/после установки. Перезапустить приложение и повторить проверку.
4. На тестовых треках сделать быстрые изменения плейлистов и текстов, свернуть приложение, открыть снова, повернуть экран, проверить сохранность. Не использовать основные уникальные данные для разрушительных испытаний.
5. Сразу после изменения TXT/LRC сделать резервный ZIP и убедиться, что он содержит свежие изменения (барьер сохранения).
6. Запустить авто-сканирование на фоне работы с плейлистом. Изменения плейлиста не должны пропасть.
7. Создать **битый JSON** и аварийное завершение процесса только на тестовом устройстве/эмуляторе. При невозможности прочитать JSON приложение не должно молча создавать новую пустую медиатеку. Замерить длительность сканирования 1000/5000/20000 файлов и отклик UI.
8. Импорт/откат ZIP и последующую миграцию Room испытывать **только на тестовой установке**, не на единственном основном телефоне.

**Нельзя:** `adb uninstall`, `pm clear`, `git reset --hard`, заменять ID существующих треков или менять `applicationId` на этом шаге. Резервные копии установщика внутри единственного каталога `C:\Users\Oleg\Documents\AndroidProjects\FreeLocalPlayer\.patch-backups`.
