# FreeLocalPlayer — 0-C.4: подтверждаемая запись пользовательских изменений

## Проблема

Ранее `LatestSnapshotWriter.submit()` только ставил снимок медиатеки в очередь. Полноэкранный редактор TXT/LRC закрывался непосредственно после вызова `onSave`, хотя `SharedPreferences.commit()` ещё не завершался. При сбое записи UI не отличал несохранённую правку от сохранённой.

## Исправление

- `LatestSnapshotWriter.submit(snapshot, onPersisted)`: callback `Result<Unit>` приходит **после** попытки записи, а не при постановке в очередь. Подтверждения для нескольких быстрых снимков, объединённых в последний, не теряются. В случае ошибки всем соответствующим запросам поступает failure. Callback не должен блокировать writer; исключения callback локализованы.
- `LibraryStore.saveConfirmed`: связывает callback с фактическим `SharedPreferences.commit()`. Сначала записывается канонический JSON, затем независимо обновляется теневая Room. Ошибка Room не отменяет успешное сохранение JSON.
- `MainActivity`: для библиотечных изменений сообщает о неуспешной записи; успешное сохранение плейлистов и TXT/LRC подтверждает только по callback. Текстовый редактор получает отдельный callback результата.
- `LyricsPanel`: пока запись ожидается, кнопка «Сохранить» недоступна, на экране «Сохраняю…»; при failure окно и текст правки остаются доступными для повторной попытки. При success редактор закрывается.
- Автоматические TXT/LRC правки внутри музыкального режима используют обычный код `changeLibrary`, который теперь выводит «Текст сохранён» только после успешного commit; отдельные диалоги тайминга пока могут закрыться до подтверждения — это отдельный UI-подэтап.

## Границы защиты

Текущая версия сохраняет быстрый оптимистический показ изменений медиатеки в Compose. При невозможности сохранения на диск текущая UI-модель не откатывается автоматически, поскольку это могло бы удалить более поздние изменения. Пользователь получает сообщение об ошибке и в редакторе может повторить сохранение. В случае внезапной гибели процесса **до завершения `SharedPreferences.commit()`** последняя правка всё ещё может быть потеряна: механизм не делает все операции синхронными. Этот этап устраняет ложное подтверждение записи, а не обещает гарантированное восстановление после отключения питания.

## Не меняется

`applicationId`, версия `1.3.12(20)`, release/debug подпись, UUID, Room schema, JSON/SAF ZIP формат, разрешения файлов, существующие медиа. `ROOM_PRIMARY_STORAGE=DISABLED_JSON_CANONICAL`. Только один каталог FreeLocalPlayer, резервные файлы — под `.patch-backups`. Эмулятор не используется.

## QA

- 4 JVM unit-теста: ожидание фактической записи, слияние запросов, ошибка записи, исправление после failure.
- 3 instrumented-теста на физическом Motorola: callback при `SharedPreferences.commit()` на специально названных QA-настройках; искусственная ошибка; слияние запросов.
- Перед заменой APK — реальный SAF ZIP и сравнение сертификатов APK. После инструментальных тестов проверка SHA-256 реального `shared_prefs/local_library_v1.xml` до/после. В инструментальном наборе нет обращения к основной базе пользователя.

Статус до фактического журнала пользователя: **подготовлено, Android Gradle/телефонная QA не подтверждены**.
