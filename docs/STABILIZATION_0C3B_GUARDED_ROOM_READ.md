# FreeLocalPlayer — 0-C.3-B: проверяемое чтение Room с откатом на JSON

**14 ноября 2026 · подготовка к телефонной QA · до прохождения Gradle/Android не считать принятой.**

## Основание

Ветка `main` после 0-C.3-A подтверждена в GitHub: `RoomPrimaryCutoverGate` сравнивает JSON и Room; на реальном Motorola Edge 60 Pro 14.11.2026 пользователь сообщил `REAL_LIBRARY_READ_ONLY_TEST=PASS tests=1`, `RESULT=SUCCESS SAFE_PHONE_JSON_ROOM_GATE_PASS`. Это подтверждает только один снимок данных, а не устойчивость при сбоях.

Этап **0-C.3-B не превращает Room в единственную авторитетную базу**. Он добавляет *guarded read* для постепенного включения: исходная библиотека всегда прочитывается из JSON, SQLite-копия может быть использована как `LibraryState` только после полного совпадения UUID, названий, TXT/LRC, порядка списков, удалённых записей, всех дополнительных метаданных, SHA-256 fingerprint и stamp. Любое сомнение возвращает **точно** JSON, а не пустую библиотеку. Сохранение как раньше: JSON `SharedPreferences.commit()` первым; затем транзакционное обновление Room.

## Изменения

1. `VerifiedRoomReadSelector.kt`: чистый выбор источника с четырьмя исходами `DISABLED`, `VERIFIED`, `GATE_REJECTED`, `ROOM_READ_FAILED`. Не вызывает SQLite, если функция выключена.
2. `ShadowRoomMirror.kt`: `readSnapshotWithoutRepair(Context)` читает все четыре таблицы и `shadow_stamp` из **одной** SQLite-транзакции. Перед чтением проверяет существование DB; не создаёт пустую базу, не восстанавливает повреждения, не меняет строки.
3. `LibraryStore.kt`: разделяет парсинг **канонического JSON** и выбор источника. Обновление Room происходит только *после* проверки и только по исходному JSON, а не по предполагаемому SQLite-результату. Стандартное поведение без переключателя сохраняется.
4. Опциональный ключ `local_library_v1` → `room_verified_read_0c3b` (`Boolean`) по умолчанию `false`. **В этом пакете переключатель не включается** и не добавляется пользовательская кнопка: нужен отдельный контролируемый запуск после телефона QA. Ключ может сериализоваться обычным SAF ZIP без изменения формата.
5. `LibraryStore.previewVerifiedRoomReadWithoutRepairForQa()` использует ту же схему выбора, но принудительно включает проверку *в памяти*, не меняя `room_verified_read_0c3b`, JSON или Room.
6. **11** Kotlin unit-тестов: полнота полей и порядок, неверная подпись/схема/счётчики, отсутствие stamp, устаревшие тексты, дубли UUID, ошибочные Room-строки и ошибки чтения.
7. **3** инструментальных теста: единственное чтение реального persistent JSON+Room на Motorola без исправления базы; два небольших теста с *только in-memory* Room и имитацией повреждений, без нагрузки 5k/20k.

Никакого изменения `applicationId`, Kotlin namespace, schema v1, `versionCode=20` / `versionName=1.3.12`, подписи, структуры ZIP, пользовательских UUID, списка предпочтений AppDataBackup или интерфейса. Оригинальные медиафайлы не перемещаются.

## Консервативная установка

Патч устанавливается **только в один существующий проект** `C:\Users\Oleg\Documents\AndroidProjects\FreeLocalPlayer`. Установщик проверяет SHA-256 старых/новых Kotlin-файлов, Git main, ancestor, удалённый HEAD, отсутствие непредвиденных изменений, блокирует 5-минутный автосинхронизатор общей блокировкой `.git/freelocalplayer-sync.lock`, сохраняет старые файлы в `.patch-backups`, делает Gradle + unit + test APK и только после этого отправляет commit. До коммита при ошибке восстанавливает файлы, не выполняет `git reset --hard` и не создаёт дополнительных проектов.

После установки **на Motorola**: использовать только `tools/Verify-FreeLocalPlayer-PhoneGuardedRoom.ps1 -Mode Audit` и затем `-Mode Run`; этот скрипт проверяет модель, текущую 1.3.12(20), наличие контрольной SAF копии, подпись установленного APK и обоих собираемых APK. Только при успехе обновляет приложение `adb install -r`, без удаления, и запускает **ровно три** безопасных теста. Это не тест производительности, о работе плеера на больших медиатеках выводов не делает.

Ожидаемый результат QA: `REAL_JSON_ROOM_GUARDED_READ=PASS tests=3`, `ROOM_READ_ROLLOUT_FLAG=DISABLED_DEFAULT`, `JSON_PRIMARY=RETAINED`, `RESULT=SUCCESS GUARDED_ROOM_PHONE_3_TESTS_PASS`.

## Что ещё НЕ решено

- Отказоустойчивость при гибели процесса между коммитом JSON и завершением транзакции Room (новый read отдаёт JSON при рассогласовании, но тест process death на телефоне не проводился).
- `RoomPrimaryCutoverGate` проверяет всю библиотеку против JSON: здесь **нет** ускорения старта от отказа от JSON-сериализации; это отдельная миграция следующей версии.
- Признак включения защищённого чтения остаётся выключенным до контрольного включения с гарантией свежего SAF ZIP и возможности экстренного отключения.
- Обновление действительного `applicationId`, release-подпись, производительность 5000/20000, и факт строгого SAF Compare прошлого этапа требуют отдельного принятия.
- Если оригинальный JSON повредится, приложение по-прежнему останавливает загрузку; Room не используется как автоматическая замена без доказанной согласованности. Это намеренная защита от незаметной порчи данных.

**Решение об активации после QA:** никаких переключений на физическом устройстве до подтверждения трёх инструментальных тестов, свежей резервной копии с текущими правками, сценариев убитого процесса и проверки обратимости.
