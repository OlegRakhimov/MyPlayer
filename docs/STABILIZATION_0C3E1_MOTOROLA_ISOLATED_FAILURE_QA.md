# FreeLocalPlayer — 0-C.3-E1: отказные тесты на Motorola без эмулятора

Статус при создании пакета: **подготовлено, Windows Gradle и Android на физическом телефоне ещё НЕ проверены**.

## Почему нет эмулятора

Пользователь установил требование: все следующие QA проводить на Motorola Edge 60 Pro. Тесты отказов создают только изолированные искусственные данные, не заменяют реальные данные и не вызывают `pm clear`, `uninstall` или намеренное аварийное завершение процесса приложения.

## Состав

1. `MotorolaRoomFailureIsolationDeviceTest.kt`: 10 instrumented тестов: rollback SQL после удаления трека, rollback после записи Lyrics+playlist, устаревшая Room -> JSON, неверная подпись/счётчики -> JSON, отсутствующий stamp -> JSON, ошибка чтения -> JSON, повторное открытие отдельной QA базы, отказ сериализатора/очереди записи и восстановление, истечение lease, строгий отказ повреждённого JSON. Все входные данные синтетические.
2. `Verify-FreeLocalPlayer-PhoneFailureIsolation-0C3E1.ps1`: требует именно физическую Motorola с известным serial и версией 1.3.12(20), свежий пользовательский SAF ZIP и совпадение его SHA-256, выполняет ранее принятый `0-C.3-D` аудит, сверяет APK signing cert, читает SHA-256 production `SharedPreferences` XML до и после через **только read-only** `adb shell run-as ... sha256sum`, устанавливает **лишь тестовый APK** и запускает 10 тестов. В отличие от предыдущего QA не обновляет основной APK.
3. `Apply-FreeLocalPlayer-PhoneFailureIsolation-0C3E1.ps1`: валидирует SHA каждого файла манифеста и ставит новые файлы в один действующий проект, без перезаписи Kotlin/Room/манифеста/версии. Запускает сборку Gradle. Git push не выполняет: сначала требуется реальный журнал QA.

## Изоляция

* 9 тестов не создают постоянных файлов: используют исключительно in-memory объекты / SQLite.
* Один тест создаёт SQLite файл со случайным именем `flp-qa-0c3e1-<UUID>.db`, проверяет закрытие/повторное открытие, затем удаляет только собственный файл в `finally`. Реальная база `flp-room-shadow-v1.db` не открывается.
* Нет изменения реальных `SharedPreferences`, JSON, JSON backup/ZIP, MIDI, плейлистов или Room. Тестовая база находится в том же Android sandbox приложения, но имеет другое имя.
* Чтение хеша `local_library_v1.xml` до/после дополнительно проверяет отсутствие изменения canonical JSON в рамках запуска. Сбой `run-as` останавливает проверки ещё до установки тестового APK.
* Проверки не тестируют фактическое аварийное завершение production-процесса, перезагрузку питания или физическую деградацию накопителя: эти темы остаются открытыми.

## Ограничения приёмки

`GRADLE_BUILD=PASS` не заменяет `ROOM_FAILURE_E1_INSTRUMENTATION=PASS tests=10` и `CANONICAL_XML_UNCHANGED=PASS`. Если хоть один критерий не выполнен, 0-C.3-E1 остаётся **PENDING**; нельзя включать постоянное чтение Room.
