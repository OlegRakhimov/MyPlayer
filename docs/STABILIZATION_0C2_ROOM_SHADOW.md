# FreeLocalPlayer — 0-C.2: транзакционная копия медиатеки в Room

**Статус этого документа до установки:** пакет подготовлен и проверен локально; сборка Android/KSP, тесты на эмуляторе и производительность не подтверждены.

## Что меняется и чего не меняем

- Версия в подготовленном патче: `1.3.12` / `versionCode = 20`; пакет `com.example.freelocalplayer`, namespace и debug-подпись сохраняются.
- Подключены AndroidX Room 2.8.5 и KSP 2.2.21-2.0.5 для Kotlin 2.2.21; источники: официальная документация Room и реестр версий KSP. Схема Room v1 экспортируется в `app/schemas` при Gradle-сборке.
- Room хранит **отдельные таблицы** `shadow_tracks`, `shadow_playlists`, `shadow_playlist_items`, `shadow_retired_places`, `shadow_stamp`. Поле `id` всегда берётся из пользовательского UUID, никогда не вычисляется заново из URI или названия.
- Сохраняются порядок композиции и плейлистов, ссылки плейлистов (включая ссылки на недоступные записи), тексты TXT/LRC, sourceKey, размер, длительность, список удалённых треков и прежние позиции в списках.
- **JSON `local_library_v1` остаётся единственным источником истины.** После успешного `SharedPreferences.commit` запускается обновление Room на том же фоновой потоке. При запуске приложения Room обновляется из прочитанного JSON после завершения очереди сохранения. В случае ошибки Room логирует `ROOM_MIRROR_FAILED`, но не портит JSON и не мешает работе плеера.
- В Room новые и изменённые записи обновляются по ID и позиции; устаревшие удаляются. Все изменения находятся в одной SQLite-транзакции. После обновления таблицы читаются назад, сравниваются с первоначальной `LibraryState` и проверяются SHA-256; только после проверки записывается `shadow_stamp`.
- Данные пользователя не переносятся без возможности восстановления: **схема авторитетного хранения не меняется**, старый APK продолжает читать прежний JSON, а ZIP 0-A экспортирует только исходные данные приложения и метаданные. При импорте ZIP новая копия Room пересоздаётся из восстановленного JSON при следующей загрузке.
- Поскольку Room на этом этапе **копия**, он удваивает часть используемого места и может замедлить фоновые записи. Стабильность и реальную производительность нужно измерить прежде, чем делать Room основным хранилищем.

## Проверка безопасности и миграции

1. **До обновления:** экспортировать ZIP из текущего приложения, сохранить на компьютере и убедиться, что в нём `manifest.json` и `prefs.json`. Не удалять приложение и не менять applicationId.
2. Собрать на Windows `:app:assembleDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest --no-daemon`. Проверить KSP-генерацию и экспорт схемы Room в `app/schemas`; установка обновления только после успешной сборки.
3. Установить APK `adb install -r` поверх предыдущего и открыть медиатеку. Убедиться, что количество песен, тексты, плейлисты, избранное и аккорды на месте.
4. Скопировать Logcat и проверить `FLP_ROOM_MIRROR`: `ROOM_MIRROR_VERIFIED` после загрузки/изменения данных, отсутствие `ROOM_MIRROR_FAILED`. Эти сообщения **не являются** доказательством восстановления из ZIP.
5. На **эмуляторе** запустить инструментальный тест: `gradlew.bat :app:connectedDebugAndroidTest --no-daemon` только при выборе тестового устройства, без одновременного подключённого рабочего телефона. `ShadowRoomMigrationDeviceTest` использует **только in-memory Room** и не стирает рабочую базу.
6. На тестовой медиатеке проверить изменение TXT/LRC, добавление/переименование/удаление плейлистов, удаление/возврат трека, перезапуск и экспорт ZIP; Room должен восстановить ту же модель после очередного открытия.
7. Замерить задержки операций и место на диске для 100 / 5000 / 20000 записей; целевой бюджет принимать по измерениям, не считать текущую реализацию автоматически быстрее.
8. **До перевода чтения на Room** проверить архив ZIP на отдельной тестовой установке, ошибку миграции и rollback на отдельном устройстве, а также случай с новым MediaStore ID. После этого возможен этап 0-C.3 — переключение источника истины с сохранением обратной совместимости.

## Локальные проверки автора пакета

- 10/10 автономных unit-тестов `ShadowRoomMappingTest`: старые/новые ID, TXT/LRC, порядок списков, удалённые записи, конфликты UUID, SHA-256, неопределённый порядок SQLite.
- Kotlin-компиляция `LibraryStore`, DAO и `ShadowRoomMirror` против **минимальных тестовых Android/Room-заглушек** (не равнозначна KSP/Gradle).
- Проверка исходных SHA GitHub, целостности ZIP и SHA-256 каждого файла патча.
