# FreeLocalPlayer — 0-C.4.1: подтверждение сохранения тайминга TXT/LRC/Enhanced LRC

## Фактический риск

В 0-C.4 полноэкранный редактор текста получает подтверждение записи через `MainActivity.saveLyricsWithReceipt`. Но музыкальный редактор временных меток ранее использовал `onSaveTimedLyrics: (String)->Unit` и сразу закрывал диалоги, когда реальная запись в `SharedPreferences.commit()` ещё выполнялась. Кроме того, `MainActivity` оптимистически обновляет `entry.lyrics`, поэтому состояния `remember(lyrics)` сбрасывались **до** подтверждения, теряя предпросмотр попытки при ошибке.

## Изменение

1. `MusicModeScreen` получает существующий `onSaveLyricsConfirmed`, не создаёт вторую систему сохранения и прокидывает callback в `LyricsChordsScreen`.
2. Три режима — настройка времени строки LRC, времени слова Enhanced LRC и TXT→LRC с ручными отметками — показывают `Сохраняю…`, не разрешают повторное сохранение/закрытие во время pending, закрываются только после подтверждения сохранения.
3. При ошибке редактор остаётся открыт, метка/список отметок остаётся в нём, предлагается повторная попытка. Состояние редактора и его неизменный исходный LRC отделены от оптимистического обновления `entry.lyrics`. Изоляция по `key(entry.id)` уже реализована в `MusicModeScreen`.
4. Новый чистый Kotlin `TimingSaveReceiptState` фиксирует `sourceLyrics`, фазы READY/WRITING/FAILED/SAVED и запрещает повторное сохранение пока оно выполняется. На сохранение JSON по-прежнему отвечает существующий `LibraryStore.saveConfirmed`.

## Проверки

- Пять unit-тестов: receipt-переходы, повтор после ошибки, исходные индексы Enhanced LRC, TXT→LRC, защита от повторного нажатия.
- Три instrumented-теста **только на Motorola Edge 60 Pro**, с отдельными `__flp_0c41_*` QA-предпочтениями: настоящий изолированный Android `SharedPreferences.commit`, имитация сбоя записи слова и удержание TXT→LRC до завершения записи.
- В установщике обязательны: сохранённый SAF ZIP с подтверждённым SHA-256, строгий исходный audit 0-C.3-D **до** изменения исходников, сравнение сертификата APK, отсутствие запущенного плеера, SHA-256 канонического XML до и после QA, Git add только конкретных файлов, без force-push.
- По результатам Gradle и Android-tests необходима отдельная **ручная UI-приёмка** редакторов; автоматические тесты не доказывают реальное поведение каждого диалога.

### Важное ограничение

Гибель процесса **до** успешного `commit` по-прежнему может потерять незавершённую правку: 0-C.4.1 исправляет UI-подтверждение и повторную попытку, не создаёт транзакционный журнал невыполненных операций.
