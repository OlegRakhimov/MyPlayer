# FreeLocalPlayer — этап 0-B.1: сохранение идентичности трека

**Статус:** пакет исходников подготовлен для проверки Android Gradle и телефона; пока **не установлен**.

**Принцип:** сохранять существующие UUID, от которых зависят TXT/LRC, плейлисты, избранное, недавние, MIDI, автоаккорды, ручные исправления и смещение. Ни один файл пользовательских данных не удаляется или не переименовывается.

## Изменения

- `MediaEntry.id` остаётся UUID. Дополнительные необязательные поля `sourceKey`, `sizeBytes`, `durationMs` описывают доказательства соответствия исходному файлу, **не заменяя UUID**.
- При удалении из видимой медиатеки запись переходит в `retiredMedia` в прежнем JSON с UUID, текстом, URI, метаданными и исходными позициями в плейлистах. В обычной медиатеке/плейлистах удалённой записи нет.
- Если тот же файл **однозначно** обнаружен снова, восстанавливаются прежний UUID, текст и позиции в плейлистах. Избранное, недавние, MIDI и исправления продолжают ссылаться на старый UUID, поэтому не требуют переписывания.
- Медиа-сканер читает размер/длительность и безопасно переключается на прежние колонки при несовместимом MediaStore. Регулярные выражения компилируются один раз, поиск по индексам не перебирает все удалённые записи для каждого файла.
- Старые JSON без `retiredMedia` и метаданных читаются с прежним смыслом.
- Android: `versionCode=18`, `versionName=1.3.10`; **`applicationId=com.example.freelocalplayer` не меняется**. APK устанавливается поверх старой версии с той же подписью.

## Ограничения, которые нельзя скрывать

- Это **часть** стабильной идентичности, а не полное сопоставление после переиндексации. Когда MediaStore изменяет ID, автоматическое прикрепление правок к другой записи **не производится**, поскольку имя/размер/длительность не доказывают идентичность. Старый UUID и данные остаются в `retiredMedia` для будущего ручного подтверждения.
- У MediaStore ID возможна переработка на другое содержимое. Несовпадение известного размера/длительности запрещает восстановление старого UUID. Если метаданных прежде не было, сопоставление ограничено исходным URI/названием. Полная защита требует отдельной процедуры проверки медиа.
- Архив `retiredMedia` может увеличивать JSON. `MainActivity.changeLibrary()` и `LibraryStore.save()` пока выполняются на главном потоке: это **не исправлено**. В следующем шаге 0-C нужны фоновое хранилище и проверенная миграция в Room, без потери архивных записей.
- Отсутствующие MediaStore-файлы сами не удаляются, права SAF между разными Android-пакетами не переходят. Автоматическое исправление потерянных URI — отдельная работа.
- ZIP бэкапа 0-A содержит весь JSON библиотеки, включая `retiredMedia`, и остаётся совместимым. **Не импортировать ZIP в единственную медиатеку до проверки восстановления на тестовом устройстве.**

## Приёмка

1. Запустить скрипт установки с `-VerifyOnly`, затем установку. Нужны SHA-256 и чистая ветка Git, блокировка auto-sync, резервные копии **внутри** `.patch-backups`; Gradle `:app:assembleDebug :app:testDebugUnitTest --no-daemon` и push только после PASS.
2. Установить `app/build/outputs/apk/debug/app-debug.apk` через `adb install -r` **без** `adb uninstall` и очистки данных. Проверить `1.3.10 (18)`.
3. Прежде рискованных тестов экспортировать свежий ZIP 0-A и скопировать его на ПК. **Не удалять важные треки на основном телефоне.**
4. **На тестовом устройстве/эмуляторе:** добавить трек и LRC, поместить его в два плейлиста и избранное, удалить из медиатеки, закрыть и снова открыть приложение, повторно обнаружить через MediaStore; проверить возврат UUID, текста, позицию в плейлистах и привязанные MIDI/аккорды.
5. Два разных файла с одним названием не сливаются. Новый MediaStore ID/другой размер не получает старые исправления. Небольшие библиотеки и сканирование тысячи файлов не создают дубликатов.
6. Экспортировать ZIP после удаления и на **отдельной** тестовой установке восстановить архивную запись. Проверить отказ на повреждённом ZIP без потерь.
7. Проверить старые LRC, избранное, плейлисты, MIDI/аккорды, медиаплеер и A–B. Закрыть этап 0-B можно только после сценариев полной переиндексации и ручного восстановительного сопоставления.

**База патча:** код `MyPlayer/main` от коммита `a5e55e66d621ae020111557433ed7169448fc3fb` (0-A), с последующими коммитами документации. Локально проверено **22 Kotlin-теста**, а Android-специфичный код компилирован только с минимальными API-заглушками. Полной Android Gradle-проверки в подготовительной среде нет.
