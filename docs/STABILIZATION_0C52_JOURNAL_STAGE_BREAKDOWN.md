# FreeLocalPlayer — 0-C.5.2: измерение стоимости отдельных стадий журнала

## Зафиксированная ручная проверка

Пользователь 19.11.2026 сообщил: «все прошло, все норм» в ответ на чек-лист 0-C.5.1 — TXT/LRC, время строки LRC, время слова Enhanced LRC, TXT→LRC, тестовый плейлист, повторное открытие приложения. ## Задача 0-C.5.2

Изолированно измерить на физическом Motorola Edge 60 Pro составляющие полной журнальной записи:

- `LibraryPendingWriteJournal.stage()`: проверка предыдущего журнала, SHA-256, формат записи, синхронизация AtomicFile;
- `SharedPreferences.commit()`: подтверждённая запись канонического JSON;
- `LibraryPendingWriteJournal.clear()`: удаление журнала;
- вся журнальная последовательность, а также прямая запись без журнала.

Три синтетические библиотеки на 630, 5000 и 20000 треков. Для каждого размера — **3 прогревочных** парных итерации и **24 измерения** на каждую ветвь. Порядок ветвей чередуется (прямая запись первой / журнальная первой) для уменьшения систематического смещения. В каждой ветви данные реально меняются между вариантами A и B. Отчёт — p50/p95 каждой стадии и полного цикла. Не вводить произвольный порог «PASS» по скорости.

## Ограничения и безопасность

`LibraryJournalStageCostDeviceTest` использует случайные имена `__flp_0c52_*` для отдельных SharedPreferences и папки; проверяет валидность синтетического JSON и удаляет файлы QA в конце. Не открывает канонический пользовательский `local_library_v1` и не вызывает `LibraryStore`. Основной APK не заменяется, тестовый APK устанавливается только после проверки подписи; используется только физическая Motorola, без эмулятора.

Замеры **не включают** формирование JSON из реального `LibraryState`, Room mirror, Compose UI, проверку/восстановление на старте, нагрузку сканирования и влияние на батарею. Снимки имеют синтетические метаданные. Дополнительно записывается SHA-256 реального `shared_prefs/local_library_v1.xml` **непосредственно до и после** тестов (не сравнивается с историческим хешем, потому что пользователь уже мог легально отредактировать тексты и плейлисты).

## Интерпретация результатов

Тесты устанавливают, какая стадия даёт наибольший вклад в накладные расходы. Отдельные p50 разных стадий **нельзя** складывать и считать p50 полного цикла, поскольку измерения одной итерации могут по-разному упорядочиваться. Нельзя утверждать, что успешное завершение тестов означает приемлемую скорость для релиза. Любая оптимизация журналирования требует нового независимого QA, проверки корректного восстановления и отсутствия регрессий сохранности пользовательских данных.

Реальная QA: **ожидается журнал запуска на Motorola**.
