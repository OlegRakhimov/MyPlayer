# FreeLocalPlayer — 0-C.5.3. Изолированный профиль затрат защитного журнала

## Предыдущие фактические измерения

19 ноября 2026 года реальная Motorola Edge 60 Pro прошла 0-C.5.2: 24 измерения + 3 прогрева на 630 / 5 000 / 20 000 синтетических треков. Медиана `LibraryPendingWriteJournal.stage()` — 8.957 / 57.657 / 220.003 мс соответственно. На 20 тысячах треков полный цикл составлял 343.729 мс, из которых приблизительно 64% приходилось на `stage()`. Подробнее: `docs/STABILIZATION_0C52_JOURNAL_STAGE_BREAKDOWN.md`.

## Задача

Разделить дорогую стадию `stage()` на:

1. два SHA-256 исходного/целевого JSON — `hash_*`;
2. создание прежней JSON-обёртки с теми же полями — `envelope_*`;
3. возможное GZIP-сжатие обёртки — `gzip_*`;
4. атомарную запись с fsync сжатого кандидата — `gzip_atomic_*`;
5. чтение/распаковку кандидата с проверкой полей и контрольной суммы — `gzip_restore_*`;
6. весь экспериментальный путь до атомарного окончания записи — `candidate_write_*`;
7. независимое время *оригинального* `LibraryPendingWriteJournal.stage()` — `raw_stage_*`.

В бенчмарке участвуют 630, 5 000 и 20 000 треков в двух синтетических профилях: `repetitive` (повторяющиеся строки) и `varied` (детерминированные псевдослучайные строки). Для каждого — 3 прогрева и 16 измерений каждого варианта, порядок оригинал/кандидат чередуется. На выборке из 16 наблюдений ближайший ранговый p95 — 16-е значение (максимум), поэтому p95 не следует считать устойчивым статистическим оценивателем. Данные в тестах НЕ являются настоящей библиотекой пользователя.

## Строгие ограничения

- **Основной APK не устанавливается и производственный код не меняется.** Новые файлы: только `app/src/androidTest/.../LibraryJournalStageDeepProfileDeviceTest.kt` и этот документ.
- Кандидат хранится исключительно в случайной папке `filesDir/__flp_0c53_*`. Сжатый файл не становится новым форматом резервной копии и не участвует в загрузке реального приложения.
- Тест сверяет декодируемость синтетического каталога строгим `CanonicalLibraryJsonDecoder`, SHA-256 сохранённого payload, идентичность JSON-обёртки после GZIP roundtrip, отказ при повреждении GZIP trailer и при превышении лимита распаковки.
- Никаких `pm clear`, `adb uninstall`, `git reset --hard`, эмулятора, тестового повреждения реального JSON или незаметной смены формата journal.
- На физической Motorola проверяется точное **текущее** значение SHA-256 `shared_prefs/local_library_v1.xml` до и после тестов; идентичность основного APK сохраняется. Не требовать соответствия старому архивному SHA-256, если пользователь редактировал песни.
- После подтверждённой QA публиковать только два перечисленных файла, не затрагивая предыдущие рабочие исходники.

## Границы результатов

Время построения `LibraryState` и JSON медиатеки, фоновые операции Room, интерфейс Compose, чтение файлов/медиасканирование и расход аккумулятора в измерение не входят. `gzip_restore_*` включает чтение `AtomicFile`, GZIP-распаковку и проверку контрольных сумм; `candidate_write_*` заканчивается после синхронной атомарной записи и не включает восстановление. Раздельные p50 нельзя арифметически суммировать как p50 общего цикла.

**Ни одно улучшение сжатия нельзя внедрять, пока не доказаны безопасное восстановление после сбоя, защита от конфликта поколений, проверка размеров, отказ при повреждении и отсутствие регрессии на физической Motorola.** Успешный тест бенчмарка означает корректное измерение, а не готовность оптимизации к релизу.

Статус до реального журнала телефона: **подготовлено, Android QA не подтверждена**.
