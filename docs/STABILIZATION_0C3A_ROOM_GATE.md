# FreeLocalPlayer 0-C.3-A — ворота Room-primary, БЕЗ переключения

Дата подготовки: 14.11.2026. Статус: исходники созданы; Android Gradle и Pixel_7 QA должны быть подтверждены журналом пользователя.

## Что меняется

- `RoomPrimaryCutoverGate.kt`: новый *чистый* fail-closed алгоритм сравнения JSON и полного содержимого Room, включая порядок записей, UUID, TXT/LRC, retiredMedia, позиции и подпись транзакции.
- `RoomPrimaryCutoverGateTest.kt`: 8 автономных регрессионных тестов, включая изменённые тексты, отсутствующий stamp, неверные счетчики, orphan-запись, дубли и старую схему.
- `RoomPrimaryPreflightDeviceTest.kt`: три сценария Android: чтение JSON и существующей Room-базы Pixel_7 без изменений; отдельные in-memory базы с 5000 и 20000 синтетических треков и измерением времени.
- `Verify-FreeLocalPlayer-RoomGate.ps1`: ограничивает целевой AVD именем `Pixel_7`, запускает проверки раздельно и сохраняет полные логи внутри `.patch-backups`.

## Защитные требования

Текущий источник истины **остаётся `SharedPreferences(local_library_v1)[library]`**. В этом этапе **нет** изменений `LibraryStore`, `AppDataBackup`, `ShadowRoomDatabase`, JSON/SAF, `applicationId`, `versionCode=20`, `versionName=1.3.12`, release-signing, UI или телефона. Запрещены `pm clear`, `adb uninstall`, `git reset --hard` и перенос тестовых баз на физический телефон.

Перед запуском тестов инструмент устанавливает обновлённый `app-debug.apk` **только поверх** приложения на проверенном `Pixel_7` через `adb install -r` (новый класс проверки должен присутствовать в APK). При несовместимой подписи операция остановится, удаление/очистка приложения запрещены. Установка обновляет APK, но должна сохранять данные приложения; Android и Gradle ещё требуется проверить фактически.

В режиме реальной проверки тест **только читает** сохранённый JSON и Room-базу `flp-room-shadow-v1.db` и сравнивает их. Не вызывает `LibraryStore.load()` и `ShadowRoomMirror.tryMirror()`, иначе исследуемые строки были бы обновлены перед проверкой. Открытие БД через Room не считается гарантией полного отсутствия служебных SQLite-записей; тест намеренно не изменяет прикладные таблицы и stamp. В нагрузочных тестах базы находятся в памяти и закрываются по окончании.

`ROOM_PRIMARY_PREFLIGHT=PASS` означает только достаточное совпадение данных для **подготовки** будущей миграции; это не подтверждение долговечности SQLite при гибели процесса или двухфазной миграции, и не разрешение переключить Room первичным немедленно. Нужны отдельные регрессии процесса, архивного реимпорта и измерения производительности.

## Обязательная приёмка

1. Компиляция `:app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest`.
2. Реальный Android тест сравнения JSON и Room после ранее выполненного импорта настоящего ZIP (Pixel_7).
3. Отдельно нагрузка 5 000 и 20 000 треков. Полученные миллисекунды — измерения только на этом эмуляторе, не обещание производительности Motorola.
4. Проверка отрицательных сценариев (unit), сохранность оригинальных UUID и нулевые изменения физического телефона.

Не считать пройденным никакой тест без фактического лога Gradle и Android. Исходный пользовательский ZIP ранее имел 628 треков, 3 плейлиста, 8 приложенных MIDI/аккордов; факт выполнения `Compare` пользователь описал «всё отлично», но полный вывод этого сравнения не приложил.
