**Дата аудита:** 12.11.2026. **Основание:** замечания пользователя и прямой просмотр исходников GitHub `OlegRakhimov/MyPlayer`, `main` на момент аудита (код приложения — commit `4ccdb042fb8b81971a3e03bec265d61019101d5e`).  
**Статусы:** `ПОДТВЕРЖДЕНО` — видно в коде; `ЧАСТИЧНО` — замечание требует уточнения; `НЕ ПРОВЕРЕНО` — нужны тесты устройства/метрики; `УЖЕ ЕСТЬ` — исходное замечание устарело.
**Не является доказательством:** наличие коммита или успешный Gradle не подтверждает целостность миграции на физическом телефоне.

## 5. НОВЫЙ ПОРЯДОК И ВОРОТА ПРИЁМКИ

**Этап 0-A (строго первый):** тестовый SAF ZIP экспорт/импорт всего пользовательского состояния, проверка восстановления, без смены пакета и без удаления данных.

**Этап 0-B:** модель устойчивого ID с миграцией и сохранением **старых** внутренних UUID/связей; набор тестов сценариев смены URI, удаления, переиндексации и одинаковых файлов.

**Этап 0-C:** фоновые изменения/сохранение, статические Regex; переход на Room только после проверенного резервного копирования и миграционных тестов (Room может быть внедрён вместе с persistent ID, но миграция должна быть атомарной).

**Этап 0-D:** окончательное имя Android-пакета, экспорт/импорт в новую установку при смене package ID, постоянная release-подпись и проверка обновления без потерь; debug ключ никогда не считать релизным.

**Этап 0-E:** ViewModel/долгоживущий анализ, восстановление очереди и сессии, корректное управление жизненным циклом.

**Этап 0-F:** производительность сканирования/очереди, актуализация документации, базовые тесты доступности, манифест и ресурсы.

**Этапы 1+** (включая v10 и дальнейшие UX улучшения) возобновить лишь после основных P0 ворот. Пакет v10 на момент аудита подготовлен, но Android build/device QA не подтверждены — **не объявлять установленным**.

### Предлагаемые тестовые бюджеты (НЕ измеренные результаты)

- **Холодный старт:** определить `p50/p95` для 100, 5000 и 20000 записей на указанном телефоне; начальная цель `p95 <= 3 сек` при 5000 записях, пересмотреть по baseline.
- **UI-отзывчивость:** ноль `ANR`; отсутствие полной JSON-сериализации на main; контролировать frames >16,7 мс на 60 Гц и отчёты JankStats.
- **Сканирование:** измерить `p50/p95` в 1000/5000/20000 записей, CPU и повторный возврат через 60 сек; до замера не объявлять норматив.
- **4 минуты анализа:** раздельные метрики debug/release, время, CPU, пик памяти, изменение уровня батареи / энергозатраты на одинаковом устройстве с фиксированными условиями. Принять лимиты **после** исходных измерений, не подменять их старым логом.
- **Память:** замер peak RSS/heap на том же телефоне для медиатек разного размера; целевой порог согласовать после baseline.
- **Надёжность:** 0 потерянных текстов, плейлистов, исправлений и MIDI в тестах миграции/повторного импорта/пересканирования; rollback при ошибочном ZIP/DB.

### Строгие ограничения при работе

- **Единственный проект Windows:** `C:\Users\Oleg\Documents\AndroidProjects\FreeLocalPlayer`. Никаких соседних версионных каталогов. Резервные копии патчей исключительно внутри проекта.
- **До миграций не удалять приложение на телефоне**, не выполнять `adb uninstall`, `pm clear`, `git reset --hard` и не заменять package ID.
- Коммиты документации **не означают исправления кода**. Любая новая реализация требует компиляции Gradle, unit/instrumented тестов, проверки на устройстве и фиксации результата в карте.
